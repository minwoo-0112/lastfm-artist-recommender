데이터 A — Last.fm 2K
1. 청취 기록 정리: 잘못된 ID와 0 이하의 재생 횟수를 제외하고, 같은 사용자–아티스트 기록이 겹치면 재생 횟수의 최댓값을 남겼습니다.
2. 태그 정리: 이름과 태그의 대소문자·공백을 통일하고, 존재하지 않는 아티스트의 태그를 제외했습니다.
3. 태그 집계: 아티스트별로 어떤 태그가 몇 명에게 부여됐는지 집계했습니다.
4. 모델 입력 생성: 재생 횟수는 log(1+재생 횟수)로 변환하고, 태그는 TF–IDF 벡터로 만들었습니다. 콘텐츠 추천에는 태그가 2개 이상인 아티스트를 사용하도록 표시했습니다.
데이터 B — Last.fm 360K
1. 잘못된 기록 정리: 사용자 ID 형식, 빈 아티스트 이름, 재생 횟수를 검사했습니다.
2. 아티스트 식별 정보 정리: MusicBrainz ID의 공백·대소문자를 정리하고 형식을 확인했습니다. 사용할 수 없는 ID는 이름으로 임시 구분했습니다.
3. 사용자 표본 추출: 데이터가 크므로 사용자를 무작위로 선택했습니다. 기본 설정은 10,000명입니다.
4. A와 연결: 정규화한 이름이 모호하지 않게 대응하는 아티스트를 연결 후보로 만들었습니다. 이 중 태그가 있는 아티스트로 콘텐츠 외부 평가 데이터를 구성했습니다.
마지막으로 두 데이터 모두, 청취 아티스트가 5명 이상인 사용자를 평가 대상으로 삼고, 사용자별 이력을 "학습 약 60%·검증 약 20%·테스트 약 20%"로 나눴습니다. 난수 시드를 고정해 같은 설정으로 다시 실행하면 같은 결과가 나오게 했습니다.




A에서는 두 모델이 같은 학습·검증·테스트 분할을 사용합니다.
B의 바깥쪽 분할은 협업용, content_external_candidates 안의 분할은 콘텐츠 평가용입니다.
콘텐츠 담당은 A의 태그로 TF–IDF를 만들고 B에도 그대로 적용합니다.
user_id, artist_id를 기준으로 연결하며, artist_index는 A와 B에서 공통 번호가 아닙니다.
